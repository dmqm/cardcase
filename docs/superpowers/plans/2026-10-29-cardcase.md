# 卡柜 Cardcase 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出一个手机优先、纯静态的私人盲盒卡展馆，可导入卡片照片、按系列陈列、整柜导出备份，并用 GitHub Pages 分发。

**Architecture:** 原生 HTML/CSS/ES modules 的多视图单页应用，无构建步骤。纯逻辑（数据模型、导出格式、筛选统计、透视几何）与平台相关部分（IndexedDB、canvas、UI）严格分离，纯逻辑用 `node --test` 覆盖；数据存 IndexedDB（元数据 + 图片 Blob），偏好存 localStorage；Service Worker 缓存外壳与图片以支持离线。

**Tech Stack:** HTML、CSS、原生 JavaScript（ES modules）、IndexedDB、Canvas 2D、Service Worker、Node 22 内置测试器（仅开发期）。

**Spec:** `docs/superpowers/specs/2026-10-29-popmart-gallery-design.md`

## Global Constraints

- 无构建、无运行时依赖；只允许原生 ES modules，`package.json` 里不得出现 `dependencies`。
- 不引入外部 web font；只用系统字体（PingFang SC / Noto Sans SC / Songti / Noto Serif SC）。
- 首屏传输 ≤ 300KB（不含用户图片）。
- 单张导入图 ≤ 150KB；最长边 1000px；`image/webp` q0.8，编码不支持时用 `image/jpeg` q0.85。
- 最低支持 iOS 16 Safari、Chrome 110。
- 卡片格子固定竖版 63:88；手机（<480px）两列，桌面最多 6 列，内容最大宽 1200px。
- 配色：底色 `#0B0B0D`、展柜面 `#141417`、暖光 `#C8A96A`、隐藏金 `#E8C87A`。
- 站点名「卡柜 Cardcase」；页脚必须写「非官方粉丝项目，与泡泡玛特无关」。
- 全站中文文案。
- 只有 `style === 'secret'` 的卡片发光并计入隐藏数。
- 每个任务结束必须有一条独立可用的提交。

## Review Focus

这些是规格没说、但真实用户一定会撞上的输入，实现时按此处理，对应测试写在拥有该代码的任务里：

1. **iPhone 的 HEIC 或 8000px 原图**：`createImageBitmap` 可能解码失败或把内存打爆。期望：先降采样再处理，失败给明确中文提示，页面不崩。
2. **四角被打乱顺序或重叠**：透视矩阵退化，输出全黑或 NaN。期望：检出退化并拒绝，退回校正步骤重来。
3. **损坏的导出文件**（版本不符、缺字段、图片不是 data URL）：期望整包拒绝，现有数据一动不动。
4. **存储配额满**（iOS 上并不宽裕）：期望提示空间不足，且不留下写了一半的卡。
5. **本地日期 vs UTC**：深夜导入、或设备时区不同，`pulledAt` 仍应是用户当地的那一天。

### Task 5: IndexedDB 存储与配额保护

**Interfaces:**
- Consumes: `Card` from `js/model.js`
- Produces:

  - `saveCard(card, imageBlob) -> Promise<void>`
  - `updateCard(card) -> Promise<void>`
  - `listCards() -> Promise<Card[]>`
  - `getImage(id) -> Promise<Blob | null>`
  - `deleteCard(id) -> Promise<void>`
  - `clearAll() -> Promise<void>`
  - `class StorageQuotaError extends Error`
  - `loadPrefs()`, `savePrefs(prefs)`, `clearPrefs()`，`prefs = { series: null, style: null, sort: 'recent', motion: 'auto' }`

- [ ] **Step 1: 实现 `js/db.js`**

要点：`saveCard` 在**同一个事务**里写 `cards` 与 `images`，事务 `onerror`/`onabort` 时抛错；若错误名是 `QuotaExceededError`，包成 `StorageQuotaError('存储空间不足，先导出备份再删几张')`；事务失败不得留下半张卡。`listCards` 返回 `cards` 全量（数量级 ≤ 数百，不做分页）。`clearAll` 只清两个 store。

- [ ] **Step 2: 实现 `js/prefs.js`**

读 `localStorage['cardcase.prefs']`，`JSON.parse` 失败或字段类型不对时回落默认值；`savePrefs` 写回；`clearPrefs` 删 key。localStorage 不可用（隐私模式）时所有函数静默降级为内存对象。

- [ ] **Step 1: 渲染卡墙**

### Task 8: 导入流程（拍照 → 校正 → 表单 → 入柜）

**Files:**
- Create: `js/image.js`
- Create: `js/import-flow.js`
- Modify: `index.html`（导入层骨架）
- Modify: `styles/app.css`

**Interfaces:**
- Consumes: `computeHomography`/`applyHomography`（Task 7）、`createCard`（Task 2）、`saveCard`/`StorageQuotaError`（Task 5）、`renderGallery`/`toast`（Task 6）
- Produces:
  - `decodeFile(file) -> Promise<ImageBitmap>`（带 EXIF 方向，长边超过 2400px 先降采样）
  - `warpToBlob(bitmap, corners: Array<[number,number]>, outLongEdge = 1000) -> Promise<Blob>`
  - `blobToDataUrl(blob) -> Promise<string>`、`dataUrlToBlob(url) -> Blob`
  - `openImport() -> void`

- [ ] **Step 1: 写 `js/image.js`**

要点：`decodeFile` 用 `createImageBitmap(file, { imageOrientation: 'from-image' })`，失败时回落 `createImageBitmap(file)`，再失败抛 `new Error('这张图读不出来，换一张试试')`；超大图先画到 2400px 的离屏 canvas 再继续。`warpToBlob`：目标 canvas 尺寸取 `outLongEdge` 与 63:88 比例中较长边，逐像素反向映射（用目标到源的逆变换，避免空洞），再 `canvas.toBlob`，依次尝试 `image/webp` q0.8 → `image/jpeg` q0.85；两种都失败则抛 `new Error('图片压缩失败')`，并在 `blob.size > 150 * 1024` 时降质量重编一次（q0.65），仍超标则接受但 `toast` 提示。

- [ ] **Step 2: 写导入层三步 UI**

`openImport()` 在 `<dialog>` 或全屏层里依次展示：
1. 选图：两个按钮「拍照」（`capture="environment"`）与「从相册选」，都触发隐藏的 `<input type="file" accept="image/*">`。
2. 校正：显示图片与四个可拖拽圆角手柄（源坐标），固定编号「左上→右上→右下→左下」，画三分网格；按钮「旋转 90°」把四个点绕中心旋转重排；确认时 `computeHomography` 返回 `null` 或任一角 `applyHomography` 出现非有限值，则 `toast('四个角没摆好，重新对一下')` 并留在本步。
3. 表单：系列（`<input list>` 带 8–12 个常见系列名建议，纯文本）、角色、款式（三选一）、抽中日期（默认今天）、备注；系列为空时禁用保存。保存时 `createCard` → `warpToBlob` → `saveCard`，`catch` 到 `StorageQuotaError` 时提示且不关闭弹层、不写一半。

- [ ] **Step 3: 接进主流程**

`#fab-import` 调 `openImport()`；成功后关闭弹层、刷新卡墙、`toast('已入柜')`。取消任一步都能整层退出且不写库。
