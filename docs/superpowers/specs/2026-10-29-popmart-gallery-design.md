## 1. 意图

一个装在手机浏览器里的私人盲盒卡片展馆。用户拍下盲盒里的卡片，卡片被"陈列"进展柜，按系列排开，隐藏款发光。它既是自己的收藏记录，也是拿给同好炫耀的那一页。

成功的样子：拆完一盒，站在桌边用手机拍两张，30 秒内卡片已经在柜子里，而且看起来比原照片更像一件展品。

## 2. 使用者与场景

- 主要使用者：收藏者本人。设备是手机（iOS Safari / Android Chrome），多数时候站姿、单手、室内光线一般。
- 次要使用者：借你手机翻柜的同好，以及收到分享海报的人。没有公开分享链接——别人打开站点看到的是他自己浏览器里的空柜。
- 真实场景：拆盒后立刻记录；整理时翻柜；朋友问"你抽到啥了"时直接打开。

## 3. 目标

- G1 三步内完成一张卡：选图/拍照 → 对框 → 补信息。
- G2 50 张卡时，手机首屏可交互 ≤ 2s，滚动接近 60fps。
- G3 有展馆气质：深色展厅、暖光、玻璃展柜，卡片像被陈列，不是被贴上去。
- G4 整柜数据能导出成一个文件，并完整恢复。
- G5 纯静态，推到 GitHub 开 Pages 即可用；无服务器、无构建、无运行时依赖。

## 4. 非目标

- 不内置官方产品图鉴、官方图片、官方 Logo 等素材。
- 不做账号、云同步、后端数据库、多人协作。
- 不做可走动的 3D 展厅。
- 不做卡片自动识别（不 OCR 系列/角色）。
- 不做社交功能（点赞、评论、关注）。

## 5. 反目标

- 做成普通相册：卡片就是一堆平铺照片，没有展柜感 —— 即使功能全对也算失败。
- 静默丢数据。
- 中端手机上卡顿、白屏，或导入时崩溃。
- 首屏为了字体/装饰下载几 MB。

## 6. 功能

### 6.1 导入流程

1. 点「+ 入柜」，调起相机或相册。
2. 出现卡片比例取景框（默认 63:88，可切横/竖），带三分网格；用户让卡片四边贴合。可选的「自动找边」按钮，失败就手动。（自动找边属加分项，不阻塞主流程。）
3. 确认后进行透视校正：四个角可拖拽微调，实时预览。角点固定编号（左上 → 右上 → 右下 → 左下），另给一个「旋转 90°」按钮，消除横拍转正后可能倒置的歧义。输出最长边 1000px，webp q0.8；浏览器不支持 webp 编码时退回 jpeg q0.85。
4. 表单字段：系列（必填，带常见系列名建议列表）、角色名、款式（固定三档：常规 / 隐藏 / 特别版，不可新增）、抽中日期（默认今天）、备注。除系列外均可留空。只有「隐藏」触发金色发光并计入隐藏数；不设自定义款式，想记别的话写进备注。
5. 保存后，卡片以开箱动画飞入卡墙（≤1.2s，可点击跳过）。

### 6.2 展馆页

- 顶部：站点名、统计（总卡数 / 系列数 / 隐藏数）。
- 筛选：系列横向 chip；款式筛选；排序：最近入库 / 按系列。
- 卡墙：<480px 两列，平板 3–4 列，桌面 5–6 列，内容居中最大宽 1200px。
- 卡墙用统一竖版 63:88 格子；横版卡片在格子里完整显示（contain）并加一层暗色底衬，不裁切、不跨格。这里说的"横/竖"是卡片本身的版式，不是拍摄时的持机方向。
- 卡片 2.5D：静止时轻微倾斜 + 玻璃反光；按下时抬升、阴影加深；设备方向可用时随手机轻晃（iOS 需手势触发授权，拒绝则静默降级）。
- 隐藏款：金色描边 + 呼吸光，不抢整墙的注意力。
- 空态：一个空展柜 + 一句"第一张卡，等你放进来"。

### 6.3 卡片详情

大图、系列/角色/款式/日期/备注、编辑、删除（二次确认）、单独保存这张图、生成分享海报。

### 6.4 数据与安全

- 「数据」页：导出整柜（单个 `.json`，含 base64 图片）、导入（合并或替换）、清空（要求输入确认词）。
- 合并按卡片 `id` 处理：同 id 覆盖、新 id 追加，导入前显示「新增 X 张 / 覆盖 Y 张」让人确认。替换是清空后写入，需二次确认，并先提供「导出备份」入口。清空清除卡片、图片和偏好，回到初次状态。
- 页面内显式说明：数据只存在这台手机的浏览器里；Safari 长期不打开有被清理的风险；建议「添加到主屏幕」并定期导出。这段提示固定在「数据」页顶部，并在首次进入的空态里出现一次。

### 6.5 分享海报

canvas 合成 1080×1920 竖图：卡图 + 系列 + 角色 + 款式 + 站点署名，可保存到相册。

## 7. 技术方案

- 形态：静态站点，原生 HTML/CSS/JS（ES modules），无构建、无运行时依赖。
- 结构：`index.html`、`styles/`、`js/`（`storage.js`、`image.js`、`tilt.js`、`poster.js`、`transfer.js`、`ui.js`）、`sw.js`、`manifest.webmanifest`、`tests/`、`README.md`。
- 存储：IndexedDB 两个 store —— `cards`（元数据）、`images`（Blob）；localStorage 只存偏好（排序、筛选、动效开关）。
- 数据模型：每张卡有稳定 `id`（`crypto.randomUUID()`），字段为 `id, series, character, style(regular|secret|special), pulledAt, note, width, height, createdAt`。
- 导出格式：`{ version: 1, exportedAt, cards: [{ ...meta, image: "data:image/webp;base64,..." }] }`；偏好（筛选、排序）不随导出迁移。
- 图片处理：canvas + 手写单应性变换做透视校正，`toBlob` 压缩。
- 动效：以 CSS transform/transition 为主；`prefers-reduced-motion` 时全部关闭；陀螺仪用 `DeviceOrientationEvent`，iOS 走 `requestPermission`。
- 测试：`node --test` 覆盖纯函数（透视矩阵、导出序列化与版本校验、合并去重、筛选排序、容量估算）；UI 用手动清单在真机过一遍。
- 离线：一个极小的 Service Worker 缓存应用外壳和卡片图片，版本号用一个 `CACHE_VERSION` 常量管；新版本装好后提示刷新一次。这样断网重开也能浏览。
- 部署：仓库根目录即站点根，main 分支开 Pages；README 写清两条路（网页上传 / gh CLI）。
- 站点名：卡柜 Cardcase，页脚注明"非官方粉丝项目，与泡泡玛特无关"。

## 8. 视觉方向

- 色彩：底色 `#0B0B0D`，展柜面 `#141417`，暖光 `#C8A96A`，隐藏金 `#E8C87A`。
- 字体：系统中文（PingFang SC / Noto Sans SC）；标题用衬线（Songti / Noto Serif SC）加大字距。不引入外部 web font。
- 质感：顶部聚光渐变、卡片下方接触阴影、玻璃高光条、低透明度噪点（CSS 生成）。
- 动效克制：只服务"这是展品"这一件事。

## 9. 约束

- 手机优先；最低支持 iOS 16 Safari、Chrome 110。
- 首屏传输 ≤ 300KB（不含用户自己的图片）。
- 单张导入图 ≤ 150KB；100 张导出约 15MB，导出前提示大小。
- 相机需要 https 或 localhost —— GitHub Pages 是 https，本地开发用 localhost，没问题。

## 10. 留给构建者决定

- 具体断点数值、缓动曲线、动画时长。
- 透视校正的手柄尺寸与触控细节。

## 11. 风险

- IndexedDB 被浏览器清理（Safari 对非「添加到主屏幕」站点有 7 天不使用清理规则）→ 显式提示 + 导出提醒。
- 导出文件偏大 → 压缩参数 + 导出前估算并提示。
- iOS 陀螺仪授权被拒 → 静默降级为手指倾斜。
- 用户误点"替换"丢数据 → 二次确认 + 先给"导出备份"入口。

## 12. 验收清单

- [ ] 手机上从拍照到卡片出现在墙上 ≤ 3 步，且不需要联网。
- [ ] 50 张卡：首屏可交互 ≤ 2s，滚动无明显掉帧。
- [ ] 隐藏款有可辨识的金色发光，常规款没有。
- [ ] 横拍、竖拍的卡都能校正成正立的卡片。
- [ ] 横版卡片在竖版格子里完整显示，不被裁切。
- [ ] 导出 → 清空 → 导入，卡片、图片、款式、日期与原来一致（筛选状态不迁移）。
- [ ] 开启"减少动态效果"后无倾斜、无飞入动画。
- [ ] 断网重开页面，已加载过的卡片仍可浏览。
- [ ] 桌面浏览器打开时居中呈现，不出现横向滚动条。
